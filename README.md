# Leo Agent

Android 上的 AI 助手。不是聊天接口套壳：自带 agent harness、工作区、CPython 运行时、
记忆、提醒，以及一套能真正点屏幕的 GUI agent。

默认 DeepSeek，装上就能用。

> 本仓库只发布安装包。源码不公开。
> 以下是设计取舍，不是 API 文档。

## Harness

**循环无状态。** `Agent` 只管「调模型 → 跑工具 → 回灌 → 再调」，会话归调用方。
所以「停止 / 重试」是外部动作，不用跟循环内部状态搏斗。

**迭代上限按语义定。** 默认 50。链式任务（读文件→试→看报错→改）给 8 次会在只差
两步时停，报一句对用户毫无信息量的「达到迭代上限」。屏幕任务密度更高（看一眼 +
点一下 = 两次请求），用过屏幕工具的那一轮单独抬到 60。

**系统提示词是片段集合，不是字符串。** 记忆、工作区说明、时间、屏幕指南、提醒、
压缩摘要各自是带 `priority` 和 `maxChars` 的片段。字符预算 8000，超了从低优先级
开始丢；核心准则标为不可裁剪——宁可超一点也不能让 agent 丢掉行为规范。装配是纯函数，
返回 `ContextReport`（保留谁、丢了谁、截断谁），可断言，不靠读日志猜。

**压缩按绝对预算，不按窗口百分比。** 128k token 触发。用「窗口 80%」得先猜窗口——
同一服务不同别名、供应商改配置、新模型层出不穷，那张对照表注定长期不准。而且先
出问题的不是装不下，是成本和延迟。代价：小于 128k 窗口的模型会在压缩触发前就失败，
这是 Agent 不感知窗口大小的既有问题，不在这里假装解决。

**图片和回执各占预算。** 截图按张（默认 3），看屏文字回执按次（默认 2）。都随步数
增长，但体积来源不同：截图每张固定几千 token，回执看元素密度。合成一个旋钮等于
强迫用户接受「图片多就得留更多旧回执」。

## 工具与权限

15 个，分三类：

| 类别 | 工具 |
|---|---|
| 工作区 | `list_files` `read_file` `write_file` `delete_file` `send_file` |
| 执行 | `run_shell` `run_python` `get_current_time` `echo` |
| 能力 | `remember` `recall` `forget` `reminder` `screen_look` `screen_act` |

**权限不是一个开关，是等级到工具集的映射。** 工作区分只读 / 读写 / 完全三档：

| 档 | 授予 |
|---|---|
| 只读 | `list_files` `read_file` `send_file` |
| 读写 | ＋ `write_file` |
| 完全 | ＋ `delete_file` `run_shell` `run_python` |

等级本身不做任何事，它只决定**哪些工具出现在发给模型的声明里**。没授予的工具既不在
`specs()` 里也调不动——模型看不到它，就不会去试。这比「允许调用但返回拒绝」干净：
后者会让模型反复撞墙，还占上下文。

代码执行和删除同属最高档。多一个正交开关会让「为什么能删不能跑」无法解释；把执行
放低档更糟——用户以为只是只读，实际能跑任意命令。子进程还会继承
`MANAGE_EXTERNAL_STORAGE`，能碰工作区之外的路径。

**纵深防御。** 授权门拦一次，工具实现内部再查一次。门被绕过时得到的是明确失败，
不是真的改了文件。

**签名漂移有静态守卫。** 描述里的参数表和实现读的字段必须一致——历史上描述承诺
`scipy` 但构建里没装，模型白烧一轮。编译器和运行时都看不见这类漂移。

## 工作区

每个工作区是 `Download/LeoAgent/workplace/<目录名>/` 下的一个目录，**目录名就是
工作区名**——所以在文件管理器里新建一个文件夹，它就自动成为一个工作区。

放在公共目录是刻意的：用户要能用别的文件管理器打开、直接往里放文件。代价是
Android 11+ 写非媒体文件必须拿「所有文件访问权限」，否则表现为「目录能列、写不进去」。

由此带来一个有意为之的后果：**用户和 agent 操作同一份文件**。你在文件管理器里改了，
它下次读到的就是改后的内容。这在沙箱式的设计里是 bug，在这里是需求。

按目录划分而不是全局共享一个空间，是因为记忆、权限、会话都挂在工作区上——换个项目
就换一套记忆和一套授权，而不是把它们混成一份。

## 记忆

按工作区隔离，`remember` / `recall` / `forget` 读写。重点在检索。

**IDF 加权，不是词频。** 分数 = 共有 token 的 `ln((N+1)/df)` 之和。只有稀有词有
信息量：半个库里都出现的「用户」「喜欢」区分不了任何东西。

**分词要认出所有文字系统。** 早期用 `[A-Za-z0-9_]+`，中文被打成空集合，打分恒为 0；
更糟的是「整理时不许新增词」那条护栏因为没有可比对的东西而放行了任何内容。现在
字母类取词，中文按**字符二元组**——无空格语言成本最低的近似。

**没有语义向量检索。** 词面相似度只用来抓「换了个说法的重复」。跨语言、跨表达的
同一件事交给模型：`remember` 带 `replaces=<id>`，或整理阶段让模型提合并建议。

**注入有节流。** 默认每轮 20 条，并明确告诉模型「需要更多用 `recall`」。全量塞进
提示词是最省事的做法，也是最贵的。

## 提醒：信息与执行分开

提醒这件事拆成了两条互不干扰的线。

**执行侧只认工具调用。** 一个 `reminder` 工具管四件事（`create` / `list` /
`cancel` / `notify`），靠 `action` 区分。模型能做的只有声明意图，真正落盘到
AlarmManager 的是 native 代码——模型没有别的路径能塞进去一条提醒。

**信息侧由代码生成，不进记忆。** 每轮自动注入「未来 72 小时内最多 10 条待提醒」的
紧凑快照。它刻意**不算记忆**：内容会自然过期，而记忆的语义是持久事实。混在一起会
让整理逻辑一直要清理日程残渣。

反过来也成立——只注入不写记忆的话，明天过去之后 agent 又不知道「用户在服药」了。
所以长期事实由模型自己提炼后 `remember`，短期的由代码注入。两边都做，但**分工不
重叠**。

**面向用户的信息和面向模型的信息不是一回事。** 模型需要的是一行 `明天 08:00 · 吃药`；
用户需要知道的是「闹钟到底会不会响」。所以提醒页的主角不是列表，是三项许可各自
缺什么的卡片，每项配一句可执行指令和跳转：

- 通知权限没开 → 准点触发但**什么都不显示**
- 精确闹钟没开 → 会响，但 Doze 下可能晚几分钟到十几分钟
- 电池优化没白名单 → 部分厂商后台清掉闹钟，可能**完全不响**

这三种降级在实现里也分开建模（`Exact` / `Inexact` / `Failed`）。一律回「已设置」
的话，用户遇到「晚了半小时」或「根本没响」时完全无从判断——这是提醒类功能最伤
信任的失败形态。

**模型的输出不能直接进通知栏。** 它常带着换行、`**加粗**`、一整段话。所以有一条
纯函数负责压成一行 → 去 Markdown → 裁到 60 字。标题被系统截断时不会加省略号，
用户看到的是断在半截的句子。

## GUI Agent

**只有一个坐标空间。** 截图统一拉到 1000×1000 再送模型。此前模型看到的图被服务端
缩到长边 1568，本地 geometry 记的是原图 1248×1972，于是它按看到的图读数、我们按
原图解释，系统性偏小 1.24 倍——点击全往左上角跑，小屏偏得少、大屏偏得多，极难定位。
归一化之后，「横向 30%」无论图被缩成 993 还是 1248 都落在同一处。兼容像素输入：
值 > 1000 不可能是相对坐标，按像素解释而不是夹到边界（夹了就是静默点到右下角）。

**动作空间 13 + 1。** 点击、双击、长按、输入、粘贴、打开、拖拽、滑动、系统按键、
清空输入、等待、问用户、结束。第 14 个 `click_many`（连点 2–5 下）单独一个开关，
因为它的前提「两次点击之间界面不变」是模型自己判断的，无法验证。关掉时它从描述和
枚举里**同时消失**，不是显示出来再报错。

**风险前置拦截。** 支付、密码、验证码这类界面和文本有黑名单，判断发生在派发手势
之前。敏感内容不进剪贴板（`paste` 会让全系统读到）。

**每一下都有回执。** 点完重新看屏，比帧指纹（窄缩略图 + 容差）判断这一步生效没。
变了说明有效，没变提示换做法。把「点了个寂寞」从沉默失败变成可观测状态。

**输入逐层降级。** `ACTION_SET_TEXT` 对某些自定义输入框返回成功但实际没写进去
（返回值只表示事件已投递），所以必须读回核对；失败退到模拟按键。每一层都验证。

**自己的悬浮窗不挡自己的手。** 顶部那条进度条是最上层窗口，天然会吃掉覆盖区内的
点击、也会出现在截图里。两条都不靠「算落点躲一下」（那种做法反复失效），而是做成
构造上不可能：任务期间窗口**永久不参与输入分发**，截图时窗口**根本不存在**
（摘不掉就报错，不将就）。代价明确接受：任务进行中不能点条停止，要停回 App 里按。

## 便利用口

功能都藏在对话里，但入口不只有对话。

- **点「+」上传** 图片走系统 Photo Picker（免权限、可多选），其它文件走 SAF。选完
  直接进工作区，不要求用户先想好路径再打字。
- **文件卡片** 对话里 agent 发来的文件是可直接点开的卡片，预览页支持图片、PDF、
  Office、文本。
- **分享** 预览页的分享走 `ACTION_SEND`。这个细节踩过坑：微信只注册 `SEND` 不注册
  `VIEW`，发成 `VIEW` 的话分享面板里永远没有微信。
- **悬浮条** 任务进行时屏幕顶部有一条胶囊，标记当前在思考还是跑哪个工具。绿色跑、
  紫色待、红色是你停了。宽固定、只换字，半透明不抢戏；整条都是触摸目标（30dp 高的
  条里塞按钮基本等于点不中）。已停时点一下 = 「继续」，和主界面的按钮是同一套语义。
- **提醒通知** 点开直达提醒页，而不是回到聊天页让用户自己找进去。
- **工作区目录** 就是 `Download` 下的普通文件夹，文件管理器可以直接往里丢东西。
- **侧栏** 工作区和会话平铺切换；宽屏并排，窄屏浮层。

| 权限 | 用途 | 必须 |
