# Leo Agent

一个 Android 上的 AI 助手。不同于「接一个聊天接口套个界面」，它围绕一套自己写的
**agent harness** 组织：模型不只是回答问题，而是能读文件、写文件、跑代码、记住事情、
定时提醒你，必要时还能看见并操作手机上的其他 App。

默认开箱即用（内置 DeepSeek 配置），装上就能对话。

> 本仓库只发布安装包，源代码不公开。
> 下面写的是**设计取舍**，不是 API 文档——实现细节会随版本变化，但这些判断不会。

## 一、Agent harness：把「一轮对话」当成一整套工程问题

大多数「AI App」的实现是：把历史消息拼成一个数组，发出去，拿回来。这在单轮问答里
够用，一旦模型开始调工具就会崩——循环停不下来、上下文越滚越大、出错后无法重试、
截图一多就直接超窗。所以这里的 harness 有明确的分工：

**一个无状态的循环。** `Agent` 不持有会话，只管「调模型 → 执行工具 → 把结果回灌 →
再调模型」这一条事件流。会话历史由调用方持有，同一个实例可以服务多个会话。
这样「停掉这一轮」「重试上一条」都变成外部可控的动作，而不是跟循环内部状态搏斗。

**迭代上限是有语义的，不是随便定的数。** 默认 50 次，因为 agent 的活天然是链式的：
读几个文件 → 试一次 → 看报错 → 改 → 再试。给 8 次会让它在任务只差两步时停下来报
「达到迭代上限」，而这个错误对用户毫无信息量——他没做错任何事，是预算先到了。
屏幕操作的往返密度更高（看一眼 + 点一下就是两次请求），所以一旦这一轮用过屏幕工具，
上限会单独抬到 60。

**系统提示词不是一个字符串，而是一组可裁剪的片段。** 记忆、工作区说明、当前时间、
压缩摘要各自是独立的片段，带**优先级**和**字数上限**。预算不够时按优先级从低到高丢弃，
而核心行为准则标为「不可裁剪」——宁可超一点，也不能让 agent 丢掉行为规范。
这一层被抽成纯函数，因此「这一轮到底丢了什么」是可测的，不靠读日志猜。

**上下文压缩按预算触发，不按窗口百分比。** 用「窗口的 80%」来判断很自然，但窗口大小
本身就得猜（同一个服务不同别名、供应商偷偷改配置、新模型层出不穷），维护一张
「模型名 → 窗口」的表注定长期不准。而且真正先出问题的不是「装不下」，是**成本与延迟**：
每轮重发全部历史，token 线性增长。所以阈值是一个与模型无关的绝对预算（128k）——
对任何 64k 窗口以上的模型都安全，同时保证单轮请求的规模可预期。

**图片和长文本各自占预算。** 历史截图按「张」计，看屏的文字回执按「次」计。两者都会
随步数线性增长，但体积来源完全不同：截图是每张固定几千 token，回执是「屏幕元素越多
越长」。合成一个「屏幕历史长度」的旋钮很诱人，代价是逼用户接受「图片多就得留更多旧
回执」这种无关耦合。

## 二、记忆：不是「向量数据库」，是一套可解释的打分

记忆按工作区隔离，模型通过 `remember` / `recall` / `forget` 三个工具读写。关键设计在
**检索**这一侧：

打分用 IDF 加权（`ln((N+1)/df)`），而不是朴素词频。理由是只有**稀有词**能提供信息——
在半个库里都出现的「用户」「喜欢」区分不了任何东西，只出现在一条记忆里的词则几乎
锁定了它。

分词必须认出所有文字系统。早期实现用 `[A-Za-z0-9_]+`，结果每一行中文都被切成空集合，
打分恒为 0；更糟的是「整理时不许新增词」那条护栏因为没有可比对的东西而**放行了任何
内容**。现在字母类文字取「词」，中文（无空格）另按**字符二元组**处理——成本最低、
效果足够好的近似。

这里刻意**没做**语义向量检索。跨语言、跨表达的「同一件事」识别交给模型自己：
`remember` 时可以带 `replaces=<id>` 改写旧条目，整理阶段也会让模型提出合并建议。
词面相似度只用来检测「换了个说法的重复」，不假装能理解语义。

注入也是节制的：默认每轮最多带 20 条，且明确告诉模型「需要更多用 `recall` 查」。
把整个记忆库塞进提示词是最省事的做法，也是最贵的做法。

## 三、提醒：把「不确定」如实告诉用户

提醒功能的难点不在定时，在**失败方式**。所以这里对每一种降级都单独建模：

| 登记结果 | 实际表现 |
|---|---|
| 精确闹钟 | 准点 |
| 降级（没有精确闹钟权限） | 依然会响，但 Doze 下可能晚几分钟到十几分钟 |
| 登记失败 | 永远不会响 |

如果一律回「已设置」，用户会在「晚了半小时」或「根本没响」的时候完全不知道原因——
这正是提醒类功能最伤信任的失败方式。

依赖的三项系统许可也是分开解释的，各自给一句可执行的指令和跳转按钮，而不是笼统一句
「权限不足」：通知权限没开 → 闹钟准点触发但**什么都没显示**；精确闹钟没开 → 会响但
可能延迟；电池优化没白名单 → 部分厂商会在后台清掉闹钟，可能**完全不响**。

技术上是 `setExactAndAllowWhileIdle`（`setExact` 在 Doze 下会被推迟到下一个维护窗口），
并且 PendingIntent 的身份同时用 `requestCode` 和 `Intent.data` 两重区分——单靠前者
在条数多了之后会碰撞，表现为「一条响两次、另一条不响」。

## 四、GUI Agent：让模型点对地方

这是整个项目里最容易出错、也最值得说的部分。

**坐标只有一个空间：把截图统一拉到 1000×1000，再送模型。** 这一步消掉了一整类 bug。
在此之前，模型看到的图（服务端会把长图缩到长边 1568）和我们记录的尺寸（原图
1248×1972）不一致，于是它按看到的图读数、我们按原图解释，系统性偏小约 1.24 倍——
点击全偏到左上角，而且小屏偏得少、大屏偏得多，极难一眼看出根因。现在模型说
「横向 30% 处」，无论那张图被缩成 993 宽还是 1248 宽，落点都是同一个地方。

**动作空间是有限而显式的。** 13 个基础动作（点击、双击、长按、输入、粘贴、打开、
拖拽、滑动、系统按键、清空输入、等待、问用户、结束），加一个可选的第 14 个：
`click_many`（一次连点 2–5 下）。后者单独一个开关，因为它的前提——「两次点击之间
界面不变」——是模型自己判断的，而这个假设无法验证。关掉时它从**描述与枚举里同时
消失**，不是显示出来然后报错：留着不删等于教模型去试一个永远失败的动作。

**风险是分级拦截的，不是「开了权限就放飞」。** 支付、密码这类界面会被识别出来并单独
对待；执行关键动作前会先问用户。这些判断在派发手势之前完成，而不是事后补救。

**每一下都要有回执。** 点完之后重新看屏，对比帧指纹（很窄的缩略图，带容差）判断
「刚才那一下生效了没」。界面变了说明上一步有效，没变则提示模型换一种做法。这一步把
「点了个寂寞」从沉默失败变成可观测的状态。

**输入框降级是逐层的。** `ACTION_SET_TEXT` 对某些自定义输入框返回成功但实际没写进去
（它的返回值只表示「事件已投递」），所以需要读回核对；失败则退到模拟按键输入。
每一层都要验证，不能相信任何一层的返回值。

**我自己的进度条不能挡住自己的手。** 任务进行时屏幕顶部会有一条胶囊进度条，它是悬浮窗。
派发手势时有一段短暂的穿透窗口，否则点击可能落在进度条上而不是下面的应用。

## 五、剩下的部分

- **文件**：有一个工作区（`Download/LeoAgent/workplace/`）。可以发图片、PDF、Word、
  Excel、压缩包给它，也可以让它自己读写删。
- **代码**：打包了完整的 Python 3.11 运行时（numpy / pandas / matplotlib / requests /
  lxml / openpyxl / python-docx / pdfplumber 等），「算一下这个」「画个图」「合并这份
  Excel」都可以直接让它做，不需要另装环境。也可以跑 shell。
- **对话**：流式输出、Markdown 渲染、长按选择、复制、重新生成、改写。支持思考型模型——
  推理过程折叠成一行，想看再展开。
- **配置**：默认 DeepSeek，也可以在设置里换成任意 OpenAI 兼容服务（OpenAI、通义、
  本地 vLLM、Ollama…）。

## 六、权限

| 权限 | 用途 | 是否必须 |
|---|---|---|
| 网络 | 访问模型服务 | 必须 |
| 通知 | 定时提醒 | 可选 |
| 所有文件访问 | 读写工作区（Android 11+ 写非媒体文件需要） | 可选 |
| 无障碍服务 | 看见并点击屏幕 | 默认关闭 |
| 悬浮窗 | 任务进行时显示进度条 | 可选 |

**没有**后台定位、通讯录、短信这类权限。
